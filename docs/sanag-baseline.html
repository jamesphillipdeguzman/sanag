SANAG

Satellite Analytics for Nightlight & Assessment Grid
Scope: Panay Island (Aklan, Antique, Capiz, Iloilo) Course: CSE 499 Senior Capstone Milestone: Week 1 Architecture Baseline

Executive Summary

SANAG is a public-benefit geospatial intelligence web application engineered to assess power grid resilience and disaster recovery across Panay Island. By transforming NASA Visible Infrared Imaging Radiometer Suite (VIIRS) nighttime light composites into quantifiable recovery curves, the platform replaces delayed manual surveys with objective, automated satellite-derived recovery metrics.

2. Processing Workflow: Three Recovery Windows

  • Window 1: Pre-Disaster Baseline (Tbase): Spans 15–30 days prior to event onset. Extracts clear-sky average radiance across each municipality to establish standard operating light levels (L̄base).
  • Window 2: Disaster Impact (Timpact): Spans Day 0 to Day +2 (peak hazard impact or transmission grid collapse). Captures minimum radiance (Levent) to evaluate drop severity:
    Outage Drop % = (1 - Levent / L̄base) × 100
  • Window 3: Restoration Horizon (Tpost): Spans Day +3 through Day +14. Evaluates daily recovery ratio R(t) = L(t) / L̄base, tracking the duration required to achieve sustained stability (R(t) ≥ 0.90).

4. Technology Stack Justification

Layer Technology Operational Rationale
Geospatial Data Google Earth Engine (Python API) Cloud-side satellite queries without storing massive raster tiles locally.
Backend API FastAPI (Python) Lightweight, asynchronous performance with built-in schema validation.
Database SQLite & GeoJSON Zero-maintenance local storage for rapid development and boundary mapping.
Frontend Vanilla HTML5, CSS3, JS Zero-framework design optimized for mobile devices and slow data connections.
Visuals Leaflet.js & Chart.js Minimal JavaScript overhead for interactive mapping and bounce-back trends.
AI Summaries Gemini 2.5 Flash (AI Studio) Automated plain-language disaster briefing reports via free-tier API.

5. Four-Sprint Implementation Plan (Weeks 2–5)

  • Sprint 1 (W2): Authenticate Earth Engine, ingest VIIRS data for Jan 2024 blackout, and mount base Leaflet map.
  • Sprint 2 (W3): Build recovery index math engine, configure SQLite storage, and expose REST API endpoints.
  • Sprint 3 (W4): Map municipal boundaries, implement Red/Yellow/Green choropleth, and bind Chart.js curves.
  • Sprint 4 (W5): Integrate Gemini API briefing card, optimize for mobile data, and deploy to staging.
